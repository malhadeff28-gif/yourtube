# YourTube

YourTube is an early local prototype for finding YouTube videos related to what you're working on. It watches new user messages in local Codex Desktop chats (when you opt in), infers a general topic, searches for videos, and displays a feed organized by project.

The idea: turn the context in an ongoing work session into a useful starting point for learning, without requiring a separate search every time the work changes. A simple title/channel keyword signal reranks verified candidates; ties retain provider order. It does not judge video quality or meaning. Recommendations are experimental and their quality has not been established.

## How it works

1. When **Live** is enabled, the local service watches for new user messages in Codex Desktop session files on this computer. It normally starts at the end of existing files, but an in-place rewrite can cause older or paused text to be read later.
2. A Codex invocation reads a short chat excerpt and the local feed’s stored project IDs, names, and tasks to identify a general work or study topic. The excerpt, names, and tasks receive best-effort redaction; IDs do not. Review the proposed project assignment and details, and review, edit, or cancel the search phrase before a separate search-enabled Codex invocation receives it. If verified videos are found, the approved project name and task replace the selected stored project’s details; selecting a new project creates one. That invocation may send the phrase or queries derived from it to search providers.
3. The service checks video IDs against YouTube's public oEmbed endpoint, then updates a local feed. You can edit project context, add videos, save videos for later, mark videos watched, and pause live reading.

While Live is enabled, YourTube normally waits for 12 seconds of quiet before processing queued chat activity. Continuous activity no longer postpones a pending batch indefinitely: after 60 seconds the batch becomes eligible, although an already-running job must finish first. This can trigger Codex processing during sustained activity and consume your account allowance. Queue limits and other watcher limitations still apply; this does not guarantee message delivery or recommendation quality.

This prototype is local software, not a hosted product or a YouTube integration. It depends on an installed, signed-in Codex CLI, web search, YouTube, and the current local Codex Desktop chat format. Those integrations may change. Video metadata verification does not verify the content or its relevance. If some candidates cannot be verified, YourTube keeps only verified results and warns that they may be incomplete; it cannot determine why verification failed.

## Run locally

Requires macOS, Node.js, Python 3, `curl`, an internet connection, and a signed-in Codex CLI with access to web search. No YouTube API key is used.

```sh
git clone https://github.com/malhadeff28-gif/yourtube.git
cd yourtube
node server.js
```

Open [http://127.0.0.1:8765/](http://127.0.0.1:8765/). The app starts with an empty feed and live chat reading **paused**. Live always starts paused after a service restart, even if it was enabled before; after reading the privacy section, click **Live**, review the disclosure, and select **Enable Live** to enable it for the current run. Canceling the dialog leaves Live paused. Stop the server with Ctrl-C.

To edit a project from **All projects**, choose the project in the picker first. Project deletion is temporarily unavailable while its safety is improved.

Use **Edit details** on a browser-added video to change its title, channel, or reason for that project. These edits stay in this browser and do not change the server’s Live feed or other project associations.

Use **Add note** on any video to save a note for that video and project in this browser. Notes are excluded from project exports unless you explicitly choose to include them and are not sent to Codex; browser site data is not encrypted. Project deletion is temporarily unavailable; existing browser notes are preserved.

Use **Copy to project** to add a video and its current details to another project in this browser. This does not change the Live feed; Watch later and Watched remain shared by video. Removed or already-associated videos are not copied.

Use **Watched** on a video to mark or unmark it in this browser, and the **Watched** filter to see videos you marked. Marking is manual and reversible; playback does not mark videos watched. Watch Later is separate.

Project and video status filters work together: choose a project and **Watch later** or **Watched** to see the intersection. **All projects** clears only the project filter, and **All videos** clears only the status filter. **For you** in the sidebar clears both.

To request videos without reading chats, select **Find videos for a project** while Live is paused and enter a general public topic. Selecting **Search** sends the phrase to Codex and may send it to web search providers; YouTube receives candidate video IDs for metadata verification. This uses your Codex allowance. Search results remain in the service’s memory for up to ten minutes. Open a candidate on YouTube in a new tab to review it; doing so connects to YouTube. Choose individual results and any available project, then select **Save selected videos** to add them in this browser; the search does not change the server feed or project details used by Live. Removed or already associated videos are not re-added automatically. The project selector shows the stored Live name and task alongside any browser overlay. If a selected project changes, use **Refresh projects** and choose it again; your search and selected results remain in the dialog. Snapshot checks cannot detect an identical same-ID project recreated with identical details. Manual search and Live work do not run together; cancellation may take time and local dismissal does not stop a search.

Video thumbnails are off by default. Enable **Load video thumbnails from YouTube** to show them; this sends video IDs and your IP address to YouTube as the feed loads. The preference is saved in this browser. Turning thumbnails off does not prevent explicitly playing a video, or Live and manual search requests, from contacting providers.

To share a readable list, select **Export a project**, choose a project, review the preview, and download the local text file. The export includes the project name and all non-removed project videos, even those hidden by the current search or view filter, with their titles, channels and YouTube links; it excludes project tasks and project notes. You can opt in to include personal video notes; review the preview because the downloaded text file is unencrypted. It is a snapshot from this browser tab, not a complete backup.

To preserve the browser's stored state even when editing is blocked, select **Export browser data**, read the privacy notice, then choose **Reveal local snapshot**. The preview and optional downloaded file contain a version 1 JSON envelope whose `raw` string preserves the exact `yourtube.state.v1` value at the time of reveal. It can include every browser project, task, private note, removal record and pending-deletion token, and is unencrypted. It excludes the Live server feed, chats, other browser keys and unsaved drafts. The snapshot is not a complete backup and there is no restore/import or deletion-recovery feature. It is limited to 2 MiB without truncation and remains available if the local feed fails to load. Keep the file private.

For a no-chat example, select **Try a sample feed** on an empty feed or visit [the sample page](http://127.0.0.1:8765/demo.html). It contains static example videos and makes no model or YouTube requests until you choose an external video link.

Run the isolated startup and privacy-control checks with `node --test tests/*.test.js`. They use a temporary synthetic session and a fake Codex executable; they do not read your chats or contact a model.

Run `node evaluation/relevance.js` to compare provider order and lexical reranking on a small, hand-labeled synthetic fixture. These examples are a reproducible smoke check, not evidence of real-world recommendation quality.

An isolated acceptance harness can exercise the complete flow with fake services or, explicitly, a real Codex search for a synthetic topic. See [live acceptance](docs/live-acceptance.md) for the commands, usage implications, and the separate manual real-chat check.

Optionally, `python3 scripts/service.py install` installs a macOS per-user LaunchAgent to run the service at login; `python3 scripts/service.py remove` removes it. Use the foreground server or LaunchAgent, not both. The installer refuses to overwrite an unrelated agent with the same label.

## Privacy and limits

- While live mode is enabled, the watcher reads new user text from local Codex Desktop chat files. Up to three recent messages per chat are briefly kept in memory for follow-ups. Pausing clears that memory and normally discards events while paused, subject to the rewrite limitation below. When Live is enabled, the service snapshots existing session files; if a new file is first discovered while Live is running, its existing contents are skipped to avoid replaying messages of uncertain age. A newly created chat’s first message may therefore be missed if it is written before the file is discovered. If the snapshot cannot be completed, Live remains paused. Replaced or visibly truncated files are also baselined; the watcher skips a read if the file changes during validation. Either case can miss messages, including concurrent appends. Session files are assumed to be append-only: a same-file rewrite that regrows beyond the previous offset between notifications may go undetected and replay old text, including text written while paused. Metadata timestamps have filesystem-dependent precision, so concurrent rewrites cannot be detected with certainty.
- The coarse missed-activity warning also appears if the watcher receives an event without a filename, queued activity is discarded, or a Live processing error prevents an update. A filename-free event may be unrelated to a chat, so the warning does not establish that a message was lost. It remains until Live is paused and cannot detect every missed event. Finding no verifiable videos is reported separately and does not by itself set the warning; metadata verification does not establish relevance or quality.
- If a watched chat file is observed missing, its queued and recent chat activity is discarded and a reappearing file is baselined. File notifications can be missed or arrive after processing begins, and work already sent to Codex cannot be recalled. Deleting a chat does not guarantee its activity will never be processed.
- Chat files are read in bounded chunks. An individual JSONL record over 1 MiB is skipped; reading resumes at the next record. This can omit unusually large messages or records.
- A short excerpt and the local feed’s stored project names and tasks are sent to Codex after best-effort redaction, before search review; project IDs are sent unchanged. Browser-only project edits are not included unless you explicitly copy the saved project name and task to the existing matching project in the local Live feed. Browser-only projects cannot yet be copied. Copying does not start Live; notes are not copied. The copy refuses to interrupt active curation and rejects a changed stored project. As with other feed updates, use a single server; other programs editing the feed are not coordinated. **Redaction can miss sensitive information.** The separate search-enabled Codex invocation receives the phrase you approve and may send it or queries derived from it to search providers; review it for private details. Pause live mode when discussing anything you do not want processed this way, subject to the rewrite limitation above. The app uses your Codex account and may consume its usage allowance.
- Recently removed lists video IDs hidden in this browser and can restore them to any still-existing project association, including their prior Watch later status when recorded. Older removals may not have that status. If no available project contains a removed video, use **Allow adding again** in Recently removed to clear its feed-wide removal after reviewing the confirmation; this restores a recorded Watch later status and may make existing or future associations appear. Individual project removals remain in place. An unresolved project deletion blocks browser edits; do not retry it or clear browser data. You can also remove a video only from the currently selected project and restore that association here; this browser preference persists if Live recommends it again and does not change Watch later or Watched.
- Project deletion is temporarily unavailable. A previously unresolved deletion remains blocked, and this version does not retry it or remove its browser data. Its project is hidden in the browser while unresolved so old local notes and edits are not shown under a reused ID; other projects remain visible. If browser state cannot be verified, all projects are hidden. Manual search, Live review and enabling Live are unavailable while this state is unresolved; Live may still be on and can still be paused. A state change after an enable request is sent cannot cancel that request. If another tab creates an unresolved intent while a dialog is open, affected text drafts are offered for copying in this tab and are lost on reload. This masks browser views only; it does not prevent the Live service from reading or updating its own feed. Restart the service and reload older tabs to use this protection; requests already in flight in an older process and external writers are not covered.
- YouTube receives video IDs for metadata verification and playback. Thumbnail requests are off by default and can be enabled in this browser; when enabled, YouTube receives video IDs and your IP address as the feed loads. No YouTube account or API key is used by the app.
- Inferred project descriptions, explicitly copied updates, and video metadata are stored locally in `dist/feed.json`; browser edits and saved videos are stored in browser site data. Neither is encrypted. The live feed and any legacy settings are ignored by Git; do not commit them. Updated YourTube tabs coordinate browser writes using Web Locks and reject stale snapshots; if locking or existing data cannot be read safely, editing is disabled. A previously pending project deletion keeps browser editing disabled; safe recovery is not yet available. Older tabs and other scripts do not participate, so use one YourTube tab per browser profile; cross-tab safety is not guaranteed with uncooperative writers.
- Codex output is temporarily written to the operating system temporary directory. The app attempts cleanup and waits briefly during normal shutdown; an error, timeout, or abrupt termination can leave a file behind. When cleanup fails or times out, live reading is paused and cannot be re-enabled in that process; stop the service and check the temporary directory before restarting. Cleanup errors are reported to the service’s standard error, which may not be visible when run as a background service.
- The server binds to loopback and is intended for a single user on their own computer. It has not been audited for shared environments. It cannot follow ChatGPT web/mobile, cloud-only chats, or messages sent while the service is stopped.

## Verification and limitations

The prototype was exercised with a synthetic local chat event through classification, search, YouTube metadata verification, feed update, and browser delivery. Pause and prior deletion behavior were also checked. The checks used a temporary feed and did not establish recommendation quality or reliable detection of every relevant message. A full reboot and a naturally occurring message in an actual Codex chat were not observed in that end-to-end test. See [TESTING.md](TESTING.md).

This repository starts from a clean feed and makes live mode opt-in. It does not include the original user's feed or browser data. The public setup and paused default have only been checked locally; broader installation and compatibility have not been established.

See [CURATION.md](CURATION.md) for implementation details. This project is unaffiliated with YouTube and OpenAI.
